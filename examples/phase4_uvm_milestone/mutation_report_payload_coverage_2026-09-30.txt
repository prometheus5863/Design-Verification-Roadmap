METHOD, and the one thing this report does differently from 2026-09-29's.
Every mutant carries a POSITIVE CONTROL ON THE MUTATION ITSELF -- a grep for
the mutated text in the mutated source, run before the suite -- because a
mutation that never arrived and a suite that cannot detect it produce the same
pass.  That rule came from the graphene repository on 2026-09-29.  The SAME
repository sharpened it on 2026-09-30 in a way that applies directly here: the
control must sit at the point of DELIVERY, not downstream, and it must be
impossible for it to pass vacuously.

A GREP-FOR-THE-NEW-TEXT CONTROL IS THE RIGHT SHAPE AND MINE WAS WRONG ON M6.
The first run of this report specified M6's control as a grep for the text the
mutation REMOVES rather than the text it INSERTS, so it reported ABSENT while
the mutation had demonstrably applied (reachability collapsed from 23 cells to
7).  Recorded rather than silently corrected, because it is the exact failure
the control exists to prevent, one level up: a control whose expected value is
wrong is not a control.  It is fixed below and the report re-run.
