TWO CONTROLS PER MUTANT, AND WHY THE SECOND ONE EXISTS
-----------------------------------------------------
The 2026-09-30 rule is that every mutant carries a positive control on the
mutation itself -- a check that the mutation ARRIVED, so that "the suite did
not fire" can be told apart from "nothing was changed".  That rule was
followed here in its 09-30 form, as control A: grep the mutated source for
the text the mutation INSERTS.

IT WAS NOT ENOUGH, AND THIS FILE'S OWN FIRST MUTATION RUN IS THE EVIDENCE.
The first version of M3 was meant to bypass the RX synchroniser.  It appended
a marker comment to the flop and rerouted only the two read sites matching
`rx_mid && rx_sync` -- which does not include the start-DETECTION read
`if (!rx_sync)`, the one place the mutant was aimed at.  Control A read
PRESENT, because the text had indeed arrived.  The suite reported the
baseline tally with 0 of 37 golden entries moved, and that was filed as an
ESCAPE: a weakness of the suite.  It was not.  The mutant was inert.

So a second control was added -- control B: the text the mutation REPLACES
must be ABSENT from the mutated source.  Control B fails on the old M3
immediately, because the flop assignment `rx_sync <= rx_in` was still there.
Rebuilt as a genuine combinational bypass it is DETECTED, and it moves 20 of
the 37 golden entries.

THE LESSON, which is 09-30's one level up: a control that greps for inserted
TEXT proves the text arrived, not that the SEMANTICS changed.  An inert
mutant and a blind suite produce the same transcript, which is exactly the
indistinguishability 09-29 and 09-30 are about -- and the mutation harness
had become an instance of the fault it was built to detect.  Control B is
cheap, it is a property of the diff rather than of the run, and it is now
required of every mutant in this directory.

6 injected, 4 detected, 2 escaped.

M2 ESCAPES AND IT IS CORRECT THAT IT DOES, which is a measured statement
about the RTL rather than an excuse.  M2 moves the rx_edge strobe and
changes NOTHING: 0 of 37 entries.  M6 moves the rx_os wrap and changes
EVERYTHING: 37 of 37, including the eps = 0 exactness check.  So the
receiver's sample cadence is set by the counter's own wrap at 15 and the
rx_edge threshold is REDUNDANT with it for sampling purposes -- the state
machine's bit boundary can be moved two ticks without moving a single
sampling instant.  A mutation of one of two redundant encodings of the same
constant is invisible by construction, and the pair is the only way to see
which of them is load-bearing.

M4 ESCAPES BY DESIGN, stated before the run: no glitch stimulus exists in
this suite, so a start-bit re-check removed cannot be seen from here.  It is
counted as an escape and not excused.

THE SUITE'S ONE NUMERIC ANCHOR IS A8.  Every other check in the file is an
inequality or a bracket, and of the four detected mutants, A8 is the ONLY
check that fires on M3 beyond the three already-failing pre-registered ones.
Without the golden table M3 would have been reported as an escape twice over
-- once for the wrong reason (an inert mutant) and once for the right one.
